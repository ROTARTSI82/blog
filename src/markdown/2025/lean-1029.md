## Types and Theory
Everything has a type. For example, `1` is a `Nat`, the type for natural numbers, and we can write
`1: Nat`.  My intuition has been roughly that types are sets of all their terms, i.e. `Nat` is roughly
the set of all natural numbers, and `1: Nat` means that $1 \in \mathbb{N}$. 

However, types themselves have types:
`Nat: Type`, but then what type is `Type`? To avoid the problem of the set of all sets that do not contain themselves,
lean uses "universes," where `Type: Type 1` and `Type 1: Type 2` and so on. In this way, we can interpret
generic types as functions on types: for example, for `List Nat` (the type of a list of natural numbers),
we can interpret `List` as `List : Type -> Type` (endofunctor moment).

Ok, but where this gets interesting is that you can actually go the other way. Being a proof assistant,
lean has a type for propositions, and `1 = 1 : Prop` means "$1 = 1$ is a proposition".
However, we can interpret `1 = 1` as the type of "proofs that $1 = 1$":


```lean
/- 5 is a natural number -/
let x: Nat := 5

/- the following is a proof for 1 = 1 -/
let my_proof: (1 = 1) := Eq.refl 1
```

Here, we prove that `1 = 1` by the reflexivity of equality, the statement that $\forall x, x = x$.
But why should we think of `1 = 1` as the type of proofs of the fact? The reason becomes
clearer when you consider `refl` itself, as in this framework it can
actually be thought of as a function:
```lean
theorem refl: (a: Type u) -> (a = a) := sorry
```
We can express the "for all" as a function from any `a` to a proof that `a = a`: `refl` is 
just a function that takes in any `a` and produces a proof that `a = a`! Notice how we use the value of `refl`'s input to determine the type of its output: `refl`
is a dependent function type, and this is the dependent type theory thing coming to play.
Here, `a: Type u` just means that `a` can be a type from any universe `u`, allowing
`refl` to be polymorphic over universes so that we can prove `1 = 1` but also that `Nat = Nat`.
Also, `sorry` is just a way to tell lean "assume this is true" (and yes, it is a type, but
that is a side tangent).

Ok, if `1 = 1` is the type for proofs that $1 = 1$, what would `1 = 2` be? There should not
exist any proofs for this proposition, so this type is *uninhabited*! This means
that it is impossible to have any instance of that type, and in fact it has a bunch of 
weird properties (see [my post on category theory if interested](/granty29/blog/2025/categories-0711/), specifically the section on initial and terminal objects. ex falso quodlibet!).
This is also how we represent `false`: it is the uninhabited type, as you can never end up
with an instance of a proof of something false. 

In lean, we consider proofs of the same fact to be equal to each other, so there is really
only one instance of `1 = 1`, as all proofs are equivalent. This makes all true propositions
have isomorphic types, and it should kinda make sense that `(1 = 1) = (2 = 2) = true` and `(1 = 2) = false`.
